A remembered version needs a real source.

An agent can invent a version, reuse a stale pin, or quietly downgrade a dependency. Version Sentinel puts a registry check into that decision.

Hallucinated versions

Ask the upstream registry before writing a version that may not exist.

Stale pins

Use a fresh lookup instead of treating model memory as current.

Silent downgrades

Require a recorded check when a version changes in either direction.

A version check records the source and decision. It does not scan packages for vulnerabilities or guarantee that a release is safe.

Check. Record. Retry.

The hook checks a local record before the tool call lands. A missing or expired check blocks the change with exit 2.

  1. Look up the registry

    Use WebSearch or fetch the upstream package page. Verify the version you intend to use.

  2. Record the check

    Run /vs-record with the ecosystem, package, exact version, and consulted source URL. Records stay in .version-sentinel/checks.json.

  3. Retry the exact version

    A record applies to its recorded version. Retry npm install lodash@4.17.21, for example. An unpinned install or latest still needs an exact version.

Deliberate older pins can use intentional:<reason>. Local paths, URLs, git sources, and workspace dependencies are outside registry-version checks.

Make the version choice explicit.

Illustrative package.json diff. The guessed 4.99.99 was absent from npm’s lodash version list when checked on 23 October 2026. The documented 4.17.21 is a historical example, not current latest.

Before / unverified

  "dependencies": {
-   "lodash": "4.99.99"
  }

A plausible-looking version is not a registry check.

After / recorded

  "dependencies": {
+   "lodash": "4.17.21"
  }

Exact version, consulted source, and a local check record.

Before you install

Have bash, jq, curl, and python3 (3.11 or later, for tomllib) on PATH. On Windows, use Git Bash for shell tools and install Python separately. Check that each required command is available.
